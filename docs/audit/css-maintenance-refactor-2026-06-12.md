# CSS Maintenance Refactor Audit

Date: 2026-06-12

maintenance refactor. This is not a visual redesign.

## Current CSS Surface

## Selector Map

- Global typography and rhythm:
  - `body`, headings, paragraphs, lists, figures, blockquotes, code, tables.
  - Affects all generated pages and posts.
- Media and content elements:
  - `img`, `figure`, `figcaption`, `iframe`, `video`, `table`, `pre`, `code`.
  - Affects old posts with inline HTML, generated tables, embedded charts, and
    newer product screenshots.
- Site layout:
  - `.page-content`, `#article`, `.wrapper`, `.post`.
  - Comes from `_layouts/default.html`, `_layouts/page.html`,
    `_layouts/post.html`, and `index.html`.
- Navigation and metadata:
  - `.post-header`, `.post-title`, `.post-meta`, `.nav-icon`,
    `#toggle-lights`, `.theme-icon-*`.
  - Comes from `_includes/nav.html`, `_layouts/page.html`, and
    `_includes/post-nav-*.html`.
- Archive list:
  - `.post-list`, `.post-link`.
  - Comes from `index.html`.
- GitHub icon include:
  - `.icon > svg`.
  - Comes from `_includes/icon-github.html`, used by `about.md`.
- Historical post hooks:
  - `figure.feel_good`.
  - Used by old and recent posts; keep unless a dedicated post audit removes it.
- Syntax highlighting:
  - `div.highlight`, `summary + .highlight`.
  - Generated by Jekyll/Rouge and used by posts with highlighted code.
- Dark mode:
  - `.dark-mode` and descendant overrides.
  - Toggled by inline JavaScript in `_layouts/default.html`.

## Findings

- The stylesheet is small but historically ordered: reset, base elements,
  tables, layout, icons, dark mode, then page-specific rules.
- Several rules are visually fragile but behavior-preserving:
  - `.post-meta { margin-top: -20px; }`
  - mobile `div.highlight` full-bleed code blocks
  - dark-mode global image opacity
  - `!important` dark-mode/layout overrides
- Multiple media queries use the same `769px` breakpoint. They can be grouped
  without changing values.
- `figure > img { display: block; }` is redundant because the global `img`
  selector already sets `display: block`.
- Dark-mode rules are scattered but should not be behavior-changed in this pass.

## Proposed Refactor

1. Reorganize `css/main.css` into named sections.
2. Keep existing values and selector behavior.
3. Group repeated media queries by breakpoint where safe.
4. Remove only confidently redundant CSS.
5. Add TODO comments to risky historical selectors instead of changing them.

- Build succeeded after the CSS-only refactor.
- Desktop smoke checks covered `/`, `/projects`, `/about/`,
  `/blog/asyncio-python`, and
  `/blog/my-python-data-visualization-kit-2024`.
- Desktop measurements preserved the expected 800px wrapper, 700px article,
  17px body font size, 34px line height, existing heading rhythm, and `-20px`
  metadata offset.
- Mobile smoke checks at 390px width covered `/`, `/projects`,
  `/blog/asyncio-python`, and
  `/blog/my-python-data-visualization-kit-2024`.
- Mobile checks preserved 390px wrapper width, 350px article width, full-bleed
  code highlighting, hidden nav labels, and responsive table header behavior.
- Dark-mode toggle still updates `.dark-mode` and `aria-pressed`, with the
  existing dark background and text colors.
- Follow-up code-rule split preserved computed `pre`, `pre code`, and inline
  `code` styling on representative code-heavy posts. Mobile full-bleed code
  blocks still measured 390px wide at a 390px viewport with no page overflow.
- Follow-up dark-mode token cleanup preserved computed dark colors for `body`,
  `.wrapper`, code blocks, inline code, highlight containers, images, and
  blockquote borders while removing redundant descendant overrides.
- Follow-up table/header polish replaced the negative `.post-meta` offset with
  explicit `.post-title` spacing while preserving the measured 7px title/meta
  gap. Table styling was simplified to horizontal rules, muted headers, and a
  grid-based mobile label/value layout. Desktop and mobile checks covered
  Markdown tables, wide compatibility tables, and generated dataframe tables.
- Generated notebook dataframe tables, such as the tables in
  `/blog/my-python-data-visualization-kit-2024`, are now scoped separately with
  `table.dataframe` rules. They share the same full-width, horizontal-rule
  table surface as Markdown tables and now use the same label/value mobile
  layout for body rows. The exported dtype header row remains visible on wide
  screens and is hidden with the rest of the header in compact mode.
